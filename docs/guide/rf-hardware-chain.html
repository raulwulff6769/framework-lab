ITles: от датчика на машине до данных в сервисе

Инженерная инструкция владельцу сервиса
Версия 1.0 · 24 сентября 2026 года

Документ описывает типовую цепочку и способы подключить уже установленное оборудование. Это не каталог гарантированной совместимости и не акт испытаний на машине.

Коротко: датчик или ЭБУ (электронный блок управления) → CAN/J1939 (цифровая сеть машины) либо входы трекера → ГЛОНАСС/GPS-трекер → SIM для M2M (межмашинной связи) и мобильная сеть → сервер-приёмник → API (программный интерфейс) ITles.

Граница доказательств. В репозитории есть декодеры реальных протокольных форматов и сквозные тесты с синтетическими данными; для части форматов используются тестовые пакеты Traccar. Названия машин, идентификаторы устройств и данные парка в platform/server/demo-fleet.json помечены как демонстрационные. Монтаж на физическую машину и полевые испытания пока не подтверждены. Поэтому точность и совместимость ниже описаны как требования к проверке, а не как уже доказанный результат [1–3].

1. Что именно передаёт данные

Датчик измеряет физическую величину (например, уровень топлива); ЭБУ — электронный блок управления двигателем, который может выдавать моточасы и другие параметры по бортовой сети. CAN — двухпроводная цифровая сеть машины. В грузовой и специальной технике часто применяется J1939, набор правил и кодов для этой сети: отдельный параметр обозначается SPN, сообщение — PGN. Сам факт наличия разъёма CAN не означает, что нужное значение доступно или регулярно передаётся: для моточасов двигателя SPN 247 некоторым ЭБУ требуется запрос; набор параметров зависит от машины и её прошивки [2, 23].

Если установлен распространённый диагностический разъём J1939 Deutsch на 9 контактов, в исполнении Type I (обычно чёрный) контакты обычно обозначены: A — масса, B — питание +12/24 В, C — CAN_H (линия высокого уровня), D — CAN_L (линия низкого уровня); скорость шины Type I — 250 кбит/с. Type II может работать на 500 кбит/с. Это ориентир для стандартного разъёма, а не универсальная распиновка всех сервисных разъёмов: сверяйте руководство машины и не подавайте питание наугад [23].

Когда CAN отсутствует или параметр оттуда не доступен, трекер может использовать:

  • дискретный вход — состояние «вкл./выкл.»; например, безопасно подключённый сигнал работы двигателя;
  • аналоговый вход — напряжение датчика, которое затем калибруют в единицы измерения;
  • RS-485 — электрический интерфейс для цифрового датчика; протокол и таблица регистров определяют, как прочитать значение. RS-485 сам по себе не означает Modbus;
  • частотный вход — импульсы с частотой, соответствующей измеряемому сигналу.

Трекер объединяет эти показания с координатами глобальных навигационных спутниковых систем (GNSS, здесь ГЛОНАСС/GPS), временем и идентификатором устройства. Обычно это IMEI — заводской номер модема/терминала. Трекер записывает точки во внутренний архив, когда сеть недоступна, и отправляет их через модем. M2M-SIM — SIM-карта и тариф для связи между устройствами «машина—сервер»; она регистрируется в сети оператора. Связь зависит от покрытия, тарифа и APN (имени точки доступа).

На сервере-приёмнике шлюз принимает TCP-соединение (сетевой канал от трекера), разбирает протокол и ставит записи в очередь; затем передаёт их по HTTPS (защищённому веб-соединению) в API — программный интерфейс обмена ITles. Либо ITles забирает данные через API существующей платформы. TCP и HTTPS — способы доставки, не названия телеметрических форматов. Нужна публичная точка приёма TCP: Vercel обслуживает веб-запросы, но не входящие TCP-подключения трекеров; шлюзу нужен VPS (виртуальный сервер с доступом из интернета) или другой сервер с открытым портом [1, 3].

Цены из интернет-магазина — только ориентир; длина, комплектация и совместимость могут отличаться [9–11].

Из платформ, к которым владелец может уже иметь доступ: Wialon Local (локально развёрнутая система), Omnicomm Online, ГЛОНАССсофт, Fort Monitor и Traccar. Traccar — открытая платформа для самостоятельного сервера; приложение Traccar Client может отправлять позиции телефона. Российские интеграторы также используют собственные платформы. Сначала выясните, где реально хранятся данные и можно ли выдать доступ только на чтение [19, 20].

Wialon Hosting не следует считать доступным из РФ по умолчанию. В уведомлении партнёрам в 2024 году указывались запрет использования в РФ с 4 июля и блокировка по российским IP-адресам (сетевым адресам) с 2 сентября 2024 года, с прекращением поддержки и взаимодействия с российским бизнесом. В проектной документации сохранён замер: 10 из 10 проверок из РФ получили код 403 (доступ запрещён) 23.09.2026. Это не гарантия для каждого адреса и не утверждение о юридическом прекращении существования компании; Wialon Local — отдельный вариант при наличии работающего сервера и доступа [1, 16].

3. Как передать данные в ITles

Прямой поток: машина → трекер → мобильная сеть → TCP-порт шлюза ITles → очередь SQLite (встраиваемая файловая база данных) → HTTPS → API и база ITles. Поток через платформу: трекер → платформа владельца → API-соединитель ITles. Второй путь обычно предпочтительнее, если существующая платформа отдаёт требуемые данные и владелец разрешает доступ только на чтение.

В текущем коде шлюз принимает Galileosky, EGTS, Wialon IPS 2.0, Wialon Retranslator и ограниченный Navtelecom FLEX 1.0/2.0. FLEX — протокол обмена Навтелекома; незашифрованный NTCB @NTC используется только для идентификации и согласования FLEX, старые команды телеметрии NTCB не принимаются. FLEX 3.0 снижается до 2.0, часть расширений не поддерживается. Соединители ITles умеют получать данные по API от Traccar, Wialon и AEMP 2.0 (стандартный интерфейс телематики производителей техники). Это не означает, что все модели бренда поддерживаются без настройки. Например, Teltonika в демонстрационном парке идёт через Traccar, а не напрямую в шлюз ITles [3, 5].

EGTS — формат передачи телеметрии, используемый в инфраструктуре спутниковой навигации РФ. Его требования описаны, в частности, в приложениях к ГОСТ 33472-2015 и ГОСТ 33465-2015. Стандарт связи не назначает каждому терминалу одно и то же поле моточасов: значение может требовать настройки счётчика по IMEI или приходить из другого источника [2, 23].

Если трекер уже передаёт данные другой платформе, сначала запросите API-доступ с правами только на чтение. Если API недоступен, настройте у провайдера ретрансляцию — повторную отправку записей на второй сервер — по EGTS или Wialon Retranslator, если это поддерживает его платформа.

Не меняйте производственный протокол Galileosky ради ITles. У него два адреса серверов, но одна настройка Protocol n действует для обоих. Если основной сервер получает EGTS, второй тоже получит EGTS; сначала подтвердите, что шлюз и маппинг ITles готовы принять именно его. Серверы обслуживаются по очереди, поэтому задержка второго потока может быть равна длительности сеанса. У Навтелеком формат можно задавать отдельно для серверов, но совместимость конкретного терминала всё равно требует проверки [2].

4. Три типовые схемы и бюджет на одну машину

Случай A. Новая машина с CAN J1939

  1. По руководству машины найдите CAN-разъём и подтвердите скорость шины, профиль J1939/FMS (FMS — согласованный профиль данных для мониторинга коммерческой техники) и доступность нужных параметров. Для моточасов отдельно спросите, выдаёт ли ЭБУ SPN 247 сам или отвечает только на запрос трекера.
  2. Выберите трекер с нужными CAN-декодером, модемом LTE и поддерживаемым выходным протоколом. Подключение к бортовой сети и CAN поручите установщику; сначала считывайте данные, не посылая управляющих команд в ЭБУ.
  3. Назначьте SIM и IMEI, настройте сервер/протокол, затем сравните моточасы с панелью и координаты с контрольным маршрутом.

Случай B. Старая машина без CAN

  1. Установщик выбирает разрешённый схемой машины сигнал «двигатель работает» — например, защищённый сигнал генератора или зажигания — и подключает его к дискретному входу трекера. Зажигание является оценкой наработки, если оно включено отдельно от двигателя; сравнивайте его со штатным счётчиком.
  2. Подберите топливный датчик по глубине и форме бака. Его RS-485 подключают к совместимому интерфейсу трекера; проверяют питание, адрес, скорость, чётность и формат данных. После монтажа бак калибруют. Не сверлите бак и не вмешивайтесь в электрическую схему без специалиста.
  3. Настройте передачу и проверьте на сервере время события, показания и дозаправку. Счётчик моточасов от дискретного входа помечайте как оценку, пока он не сверен с панелью.

Случай C. Трекер уже подключён к чужой платформе

  1. Не демонтируйте оборудование: выясните платформу, модель/прошивку трекера и доступный API.
  2. Предпочтительно подключить API с правами только на чтение. Если его нет, попросите интегратора добавить ITles как второй адрес ретрансляции по EGTS или Wialon Retranslator.
  3. Уточните, кто владеет SIM и оплачивает связь, какие датчики настроены и как считаются моточасы. Для Galileosky не меняйте общий протокол двух серверов.

5. Телефон в кабине: браузер или приложение

Разрешение на геолокацию означает, что браузеру или приложению можно запрашивать координаты; оно не запускает запись и не гарантирует фоновую работу. В Safari на iPhone 11 открытая страница может получать позицию, пока активна, но на непрерывный трекинг при свёрнутой вкладке или заблокированном экране рассчитывать нельзя: у веб-страницы нет собственного постоянно работающего фонового сервиса. Нативное приложение может запросить отдельное фоновое разрешение в iOS (операционной системе iPhone) [21].

  • iPhone: для фоновой передачи используйте Traccar Client или другое нативное приложение, которому вы доверяете. В Traccar Client задайте ID устройства и полный URL своего совместимого сервера, включите высокую точность и разрешите фоновую геолокацию, если iOS предложит этот режим. Не завершайте приложение принудительно. Прямо в ITles: на странице машины нажмите «+ Traccar Client» — ITles выдаст идентификатор устройства и адрес сервера (приём по протоколу OsmAnd, который использует Traccar Client); впишите их в приложение. Другой путь — собственный Traccar Server и подключение «Traccar» в ITles [3, 20, 21]. На iPhone откройте Настройки → Конфиденциальность и безопасность → Службы геолокации → Traccar Client; включите точную геопозицию и доступ, достаточный для выбранного сценария. Названия пунктов могут отличаться по версии iOS.
  • Android: в текущей сборке ITles запустите приложение, войдите в кабинет, откройте «Телефон в кабине», нажмите запуск и разрешите точную геолокацию и уведомления. Оставьте постоянное уведомление активным: foreground-служба — системно заметная фоновая служба с уведомлением. Если точки пропадают, в настройках приложения → батарея разрешите фон/режим «без ограничений». Службу запускайте из открытого приложения; настройки Android зависят от производителя [6, 22].
  • Резерв: Traccar Client доступен для Android и iOS и рассчитан на фоновую отправку. При отсутствии сети он может буферизовать точки и отправить их позже, если эта опция включена; энергосбережение ОС и принудительная остановка приложения всё равно создают пропуски [20].

Ограничение именно этой сборки ITles для Android: в репозитории описаны нативная foreground-служба и постоянное уведомление, однако APK проверен статически, а запуск на телефоне/эмуляторе ещё не выполнен. Координаты передаются веб-слоем: неотправленные точки ждут в очереди браузера (IndexedDB), но нативной досылки после завершения процесса нет. Сначала проверьте «последнюю фиксацию», число точек и ответ сервера с включённым экраном, затем повторите тест при блокировке и после потери сети [6].

Координаты могут идентифицировать водителя. Перед сбором получите решение владельца техники; главный администратор владельца должен управлять тем, включена ли геолокация и кому видны координаты. Правовой режим хранения и место размещения данных надо оценить до реального пилота [1].

6. Что спросить у владельца техники и как принять тест

  • Марка, модель, год машины и двигателя; показания штатного счётчика моточасов/одометра для сверки.
  • Установлены ли терминал и датчики? Точная модель, ревизия, IMEI, прошивка, свободный серверный адрес и кто отвечает за SIM.
  • Какая платформа уже используется? Можно ли получить API-токен только для чтения или заказать ретрансляцию; кто её администрирует?
  • Какой выход настроен: Galileosky, EGTS, Wialon IPS 2.0, Wialon Retranslator, FLEX — какой версии? Для Galileosky узнайте протокол действующего сервера и не меняйте его.
  • Есть ли доступный CAN/J1939 и описание разъёма; какие именно SPN/счётчики видит терминал? Если CAN нет — какой защищённый сигнал подтверждает работу двигателя?
  • Для топливного датчика: модель, длина, интерфейс, протокол/скорость, адрес и форма бака; есть ли таблица тарировки?
  • Где машина работает и какой мобильный оператор там ловит? На ком SIM, какой M2M-тариф/APN, есть ли архив и сколько истории он хранит?
  • Кто разрешает координаты, кто их увидит, где будут храниться записи и кто может отключить передачу?

Порядок приёмки: 1) сверить модель/IMEI и локальное показание; 2) увидеть TCP-соединение и распознанные записи на шлюзе; 3) убедиться, что API ITles показывает тот же источник и время события; 4) сравнить моточасы с панелью, топливный датчик — с тарировкой, координаты — с разрешённым контрольным маршрутом; 5) отдельно проверить архив и досылку после разрыва связи. Зафиксируйте протокол, способ измерения, расхождение и ограничения. Результат синтетического теста не является полевым испытанием [1–3].
