# Восстановленный контекст разработки ITles

Составлено **23.09.2026** по исходному Git, документации проекта и двум
предоставленным владельцем архивам переписки. Сырые архивы **не хранятся в Git**:
в них есть строки подключения, пароли и не относящиеся к проекту данные.
Этот обзор передаёт решения и границы доказательности, а не воспроизводит
сообщения/внутренние мысли прежних агентов. При расхождении исторического
отчёта с проверкой кода или сервиса приоритет у новой проверки.

## Принятые пользовательские решения

- Основная цель — дистанционно видеть работу и показатели машины почти в
  реальном времени, с историей и понятным временем последней точки. Сначала
  три поля исходного ТЗ; масло добавлено отдельным этапом. Кубатура харвестера,
  конкретная 1С и лабораторный обмен отложены, а не «настроены на все модели».
- Минимизировать затраты и действия владельца: первый выбор — доступный API
  действующей системы, ретрансляция/второй сервер уже установленного трекера,
  затем телефон/фото панели; новые датчики или трекер — только по
  диагностированному пробелу. Нет нового собственного устройства ITles.
- FUCHS видит сеть, дистрибьютор своих клиентов, владелец — свои машины.
  Главный администратор владельца управляет координатами, в том числе их
  передачей вышестоящим ролям. На текущем этапе не собирать имена, телефоны
  и почту водителей. Для **реальных** маршрутов/ИП вопрос персональных данных
  и региона хранения нуждается в отдельной правовой оценке.
- Интерфейс на русском, лендинг и загрузки для Windows/Android; для iPhone
  пока PWA. RuStore публикует владелец; нативное iOS-приложение не собрано.
  Тёмная карта MapLibre/OpenFreeMap заменила Leaflet, 21st.dev использовался
  для дизайн-референсов; это не договор о доступности тайлов по всей России.
- Режим CAN по умолчанию пассивный; активный запрос J1939 PGN 65253 через
  Request 59904 требует разрешения владельца машины и оценки гарантийных
  условий. EGTS не даёт стандартных моточасов без настройки счётчика;
  Galileosky выбирает один протокол для двух серверов; у Навтелеком выбор
  протокола возможен отдельно по серверу (см. [фактчек](factcheck-v2.md)).

## Исследования: что пережило перенос

Первый чат содержит восемь отчётов R1–R8 и ранние заметки по устройствам,
стандартам и тестовым данным. Оригиналы создавались во временном каталоге
прежнего рабочего пространства; переносить их **как есть** из архива с
реквизитами нельзя. Проверенные выводы уже представлены в:

| Исследование | Опорные материалы в этом Git | Что осталось проверить |
|---|---|---|
| R1 протоколы трекеров | [DESIGN-v2 §§3–5](../design/DESIGN-v2.md), [векторы Traccar](../../tests/data/traccar_vectors.json), [источники](sources.md) | Конкретный терминал/прошивка, архив и параметр моточасов у клиента |
| R2 нормы и геоданные | [DESIGN v1](../design/DESIGN.md), [фактчек v2](factcheck-v2.md) | Актуальность норм на дату пилота, правовая квалификация треков владельца |
| R3 платформы/API | [коннекторы](../../platform/server/connectors), [фактчек v2](factcheck-v2.md) | Тестовые аккаунты и реальные права Wialon Local/Traccar/AEMP |
| R4 данные и модель | [отчёт моделирования](../simulation-report.md), [таблица](../../deliverables/ITles_Fuchs_telematics.xlsx) | Независимые полевые эталоны для каждого класса техники |
| R5 связь в РФ | [фактчек §5](factcheck-v2.md) | Реальное покрытие делянки/карьера и срок хранения архива при интервале клиента |
| R6 харвестеры в РФ | [фактчек §§1–2](factcheck-v2.md), [источники](sources.md) | Комплектация выбранной машины; данные книги заказчика — выборка, не перепись 2026 г. |
| R7 независимый фактчек | [фактчек §4](factcheck-v2.md) | Снова сверять спорные модели/правила с первоисточниками при пилоте |
| R8 масляные датчики | [исследование датчиков](oil-sensors.md), [DESIGN-v2 §11](../design/DESIGN-v2.md) | Доступность в РФ, паспортные PGN/SPN/Modbus-регистры, калибровка и монтаж |

В частности, ранние утверждения «любой ЭБУ сам передаёт моточасы», «у любой
машины уже всё доступно по сети» и «можно гарантировать нулевую потерю данных
в любой зоне без связи» **не являются выводами проекта**. В модельном
сквозном прогоне 5 425 точек прошли без потерь, но журнал архива конечен;
нулевые потери на полевом парке не измерялись.

## Что нельзя восстановить по двум чатам

Вложения с исходной книгой о харвестерах и отдельными поздними материалами
не приложены к этому запуску; доступна только включённая в Git производная
таблица. Неподписанные/неопубликованные изменения из прежнего рабочего
пространства не находятся в Git, поэтому нельзя считать их протестированным
кодом или автоматически «перенести всё» вместе с приватным архивом. Для
каждого пробела из [плана](../ROADMAP.md) нужны источник, воспроизводимый
тест и отдельное решение владельца, а не неограниченное обещание точности.
